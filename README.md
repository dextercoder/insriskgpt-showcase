# InsRiskGPT 系统架构（展示版）

> 版本：v1.0 

https://dextercoder.github.io/insriskgpt-showcase/insriskgpt-showcase.html

## 1. 这份文档回答什么

只回答三个问题：

1. 保险风险决策这个问题，应该怎么拆；
2. 拆完之后，系统用什么结构承载；
3. 怎么证明这套结构是有效的、可控的。

刻意省略的内容：具体特征清单、融合权重、动作阈值、数据表结构与接口字段、验收数值门槛。这些参数强依赖具体数据分布和业务约束，脱离上下文单独展示没有参考价值。

## 2. 问题定义

保险风险决策有三个绕不开的难点：

| 难点 | 具体表现 | 对方案的约束 |
|---|---|---|
| 信号异构 | 结构化字段、病历/照片/申诉等非结构化材料、关系网络同时存在 | 单一模型无法覆盖，需要多路信号分层处理 |
| 样本稀疏、标签滞后 | 欺诈与带病投保是低频事件，结论往往在理赔甚至事后审计才回流 | 依赖标签闭环与弱监督，不能只做一次性训练 |
| 决策有外部性 | 拒保、加费、拒赔会直接影响用户，且受监管约束 | 必须可解释、可追溯、可审计，且要过公平性检查 |

由此得到一个基本判断：**这不是一个模型问题，而是一个分层决策系统问题。** 模型负责把信号变成概率，系统负责把概率变成可解释、可运营的动作。

## 3. 设计原则

1. **统一底座 + 险种插件**：特征、训练、LLM 网关、决策引擎、监控全险种共用；健康险、车险、退运险的差异收敛到插件配置，底座不写险种分支。
2. **在线决策 + 离线闭环**：在线链路一次请求内出决策；离线链路负责标签回流、训练、评估、灰度与监控。
3. **双引擎分层融合**：传统模型负责稳定的概率预估，LLM 负责非结构化理解与证据推理，融合层输出统一风险分。
4. **成本感知路由**：低风险案件只走轻量模型；有材料、有冲突或高分的案件才进入深度推理。
5. **可解释与公平内建**：每条决策都带理由码、证据和模型版本，公平性检查进入发版门禁，而不是上线后补。

## 4. 总体架构

```
业务接入   投保 / 核保 / 理赔 / 续保 / 渠道 / 运营后台
              │ 统一风险请求
决策编排   场景编排 · 规则引擎 · 模型路由 · 决策组装
              │
模型计算   传统 ML 服务  │  LLM 认知服务  │  融合与路由
              │
特征平台   离线特征 · 实时特征 · 特征血缘 · 特征监控
              │
数据底座   业务库 · 非结构化存储 · 图库 · 向量库 · 标签库

旁路：模型生命周期（标签→训练→评估→灰度→重训）
      运营监控（业务指标 · 模型指标 · 漂移 · 公平性）
```

### 4.1 在线链路

```
请求接入 → 契约校验 → 特征组装 → 轻量模型打分
→ 路由判断 → （必要时）LLM 深度核验 → 分层融合
→ 规则决策 → 返回决策、理由与证据
```

关键设计是**可降级**：LLM 超时降级为纯模型分，模型服务异常降级为规则引擎，规则也失败才转人工。降级不是异常处理，而是主链路的一部分。

### 4.2 离线链路

```
业务事件 → 标签回流 → 样本治理 → 训练 → 评估门禁
→ 模型注册 → 影子 / 灰度 → 线上监控 → 漂移告警 → 重训
```

### 4.3 统一风险契约

四类场景共用一套决策输出，至少包含：

| 字段 | 作用 |
|---|---|
| `request_id` | 幂等键，避免重复出单或重复赔付 |
| `product_code` | 险种标识，驱动插件加载 |
| `risk_score` | 综合风险分 |
| `decision` | 决策动作 |
| `reason_codes` | 结构化理由码，供运营与审计使用 |
| `evidence` | 证据链或关键特征贡献 |
| `model_versions` | 本次调用的模型版本组合 |
| `route` | 轻量路径或深度路径 |
| `latency_ms` | 处理耗时 |

统一的收益是：下游运营、审计、监控只需要对接一套结构，险种差异对它们透明。

## 5. 四大场景的建模思路

### 5.1 承保定价：把风险拆成频率和案均

直接回归保费会遇到两个问题：样本里零赔付占比高、单笔金额长尾。所以拆成两个子任务：

- **出险概率**：树模型做二分类，线性模型作为可解释基线与监管对照；
- **条件赔付**：Gamma GLM 或树模型回归；
- **纯保费**：频率 × 案均，再叠加费用与安全附加；
- **加费比例**：由目标综合成本率反解，而不是拍脑袋定档。

输出标准费率、加费、除外三档，并附风险分、加费率和定价因子贡献。树模型保证效果，线性模型保证"解释得清"，两者同时存在是有意为之。

### 5.2 智能核保：模型分 + 证据分的分层融合

核保的核心矛盾是：结构化模型看不懂材料，LLM 又不够稳定。做法是让两者各做擅长的事：

- 传统模型输出出险概率，回答"这类人整体风险多高"；
- LLM 输出证据风险分，回答"这份材料里有没有和告知矛盾的地方"；
- 融合层按险种配置权重，权重由离线评估标定，不做全局统一。

LLM 侧是固定五段式流水线：OCR/版面解析 → 按险种 Schema 抽取 → 检索条款与医学/定损/电商知识 → "告知 vs 材料"一致性校验 → 生成理由。

深度核验不是每个案件都跑，只在有材料、有告知异常、有冲突或模型分偏高时触发。动作阈值按险种分位标定，目的是把人工复核率稳定控制在可运营的区间，而不是追求单一准确率。

### 5.3 续保风险：序列建模 + 策略映射

续保不是单点分类，而是对保单存续期的持续观察。用序列模型建模月度行为序列（理赔、健康变化、互动、缴费、保障使用、渠道触达），输出三件事：

- 续保概率；
- 续保后 12 个月出险概率；
- 风险趋势（稳定 / 上升 / 下降）。

策略按续保概率分档（维持费率 / 风险提醒 / 加费续保 / 不建议续保），分档边界由业务目标校准。再引入续保价值分（续保概率 × 预期保费贡献 − 续保后预期赔付），用于精算和渠道排序。

评估不只看续保率，还要看续保后赔付率和策略组相对对照组的增量收益，避免"为了续保而续保"。

### 5.4 理赔反欺诈：四路信号并行

单一信号在反欺诈里都容易被绕过，所以做四路并行：

| 信号 | 方法 | 捕捉什么 |
|---|---|---|
| 案件级 | 树模型 | 金额、报案延迟、既往理赔、机构、诊断/事故类型等单案异常 |
| 异常检测 | 孤立森林 / 密度聚类 | 金额—频次—时间—空间上的孤立案件 |
| 关系网络 | 图神经网络 + 社区发现 | 用户、设备、手机号、银行卡、地址、IP、机构的团伙结构 |
| 材料语义 | LLM 抽取 + 多文档一致性校验 | 材料之间的矛盾与伪造痕迹 |

四路融合后按险种设置调查/拒赔阈值。**拒赔必须同时满足"高分 + 证据链"双门禁**，不允许只凭模型分拒赔——这是合规要求，也是对模型不确定性的尊重。

评估以欺诈召回优先，同时看误伤率、案件时效和单案成本，因为反欺诈的收益最终是成本账。

### 5.5 双引擎怎么分工

| 能力 | 传统模型 | LLM | 融合层 |
|---|---|---|---|
| 结构化信号 | 强 | 弱 | 不处理 |
| 非结构化材料 | 弱 | 强 | 不处理 |
| 稳定性与一致性 | 强 | 弱 | 负责校准 |
| 解释形式 | 特征贡献 | 证据引用 | 统一理由码 |
| 成本 | 低 | 高 | 负责路由与配额 |

结论：不是"用 LLM 替代模型"，而是用 LLM 补上模型看不见的那部分信号，再用路由控制它只在值得的地方出现。

## 6. 标签、样本与迭代闭环

模型效果的上限由标签决定，所以闭环设计和模型设计同等重要。

- **标签来源**：调查确认、人工复核结论、事后审计发现、赔付后追偿；
- **样本治理**：时间窗切分、偏差检测、正负样本比例监控；跨险种只迁移特征工程经验，不直接迁移模型；
- **评估门禁**：离线指标 → 历史案例回放 → 影子流量 → 灰度放量，任一环节不达标不上线；
- **线上监控**：数据漂移、模型衰减、业务指标三类同时看，漂移告警触发重训而不是等效果崩掉。

## 7. 可解释、公平与合规

- 传统模型用 SHAP 输出全局与局部特征贡献；
- LLM 的每条结论必须引用材料片段或知识库内容，低置信度自动转人工；
- 公平性按险种选择敏感维度做分组评估，关注分组通过率差异、加费率差异和 disparate impact；
- 去偏手段包括样本重加权和对抗去偏；
- 每次发版自动跑公平性与可解释性扫描，作为上线前置条件。

## 8. 关键设计取舍

| 取舍 | 选择 | 原因 |
|---|---|---|
| 单一大模型 vs 多模型分层 | 多模型分层 | 成本、稳定性、可解释性都更可控 |
| 纯模型 vs 规则兜底 | 规则与模型并存 | 监管需要确定性，异常需要兜底 |
| 全局统一阈值 vs 险种分位标定 | 险种分位标定 | 不同险种风险分布差异大，统一阈值无法运营 |
| 同步深度核验 vs 异步 | 高风险同步、其余异步 | 兼顾时效与成本 |
| 底座写险种逻辑 vs 插件化 | 插件化 | 避免底座腐化，新险种可独立接入 |

## 9. 如何验证

分三类指标，只看名称和用途，具体门槛按业务目标校准：

| 类别 | 指标 | 用途 |
|---|---|---|
| 业务 | 赔付率、欺诈率、核保人工复核率、续保率 | 判断系统是否真的改善经营 |
| 模型 | AUC、KS、欺诈召回、误伤率、PSI | 判断模型是否稳定有效 |
| 治理 | 分组通过率差异、disparate impact、证据引用覆盖率 | 判断是否可解释、可审计 |

验证方式不是只看离线指标，而是用模拟数据做端到端回放：从投保申请一路走到核保、保单、续保、理赔、材料解析、一致性校验、标签回流和重训，确认每条链路都能还原。
